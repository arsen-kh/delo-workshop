# Дело — мастерская под контролем

Личный учебный проект Арсена Хутова, созданный с помощью Codex: сервис учёта заявок ремонтной мастерской и отдельная автоматизация отчёта из CSV. Реального заказчика и подтверждённого бизнес-эффекта пока нет.

## Возможности

- Создание и редактирование заявок: клиент, телефон или email, устройство, описание, приоритет, источник, ответственный, срок и стоимость.
- Статусы: новая, диагностика, в работе, готова, закрыта, отменена.
- Поиск, фильтры и контроль просроченных активных заявок.
- Обзор текущего состояния, история изменений и защита от перезаписи устаревшей версии.
- Отчёты по периоду создания и ответственному, экспорт CSV и отдельная обработка CSV-файлов.
- Адаптивный интерфейс и шесть вымышленных примеров для демонстрации.

## Запуск на своём сервере

Готовая сборка: `server-dist/server.mjs`, статические файлы и миграции. Runtime не требует npm-зависимостей. Используются Node.js и встроенный SQLite. Проверено локально на Node.js 24.22.1 под Windows; запуск systemd/Nginx и Docker в Linux пока не проверялся.

Инструкция: [docs/UBUNTU.md](docs/UBUNTU.md). Для самостоятельного размещения соберите проект из исходников командами ниже.

Для сборки из исходников нужны Node.js 22.13+ и npm:

```sh
npm ci
npm run build:server
```

Для локального запуска создайте `.env` с `ADMIN_USER`, `ADMIN_PASSWORD` (от 12 символов) и `SESSION_SECRET` (от 32 символов); не добавляйте его в Git. При желании задайте `DB_PATH`, `PORT` и `HOST`. Без настроек база хранится в `data/workshop.sqlite`, адрес — `127.0.0.1:3000`.

```sh
node --env-file=.env server-dist/server.mjs
```

Схема SQLite обновляется при старте. Повторный запуск не очищает данные. Пароль хранится в закрытом файле окружения; вход проверяется через scrypt, сессия подписывается HMAC, cookie — HttpOnly/SameSite. За Nginx с HTTPS используется Secure cookie. Нужен один общий аккаунт; отдельных ролей и персональных кабинетов нет.

`deploy/make-env.mjs` создаёт файл настроек со случайными секретами, не перезаписывая существующий. По умолчанию он рассчитан на серверный путь базы `/var/lib/workshop/workshop.sqlite`: для запуска на компьютере замените `DB_PATH` на локальный путь.

## Автоматизация отчёта

```sh
node automation/report.mjs automation/examples/requests.csv --out report-output
```

Инструкция и описание ограничений: [automation/README.md](automation/README.md).

## Проверки

После сборки:

```sh
npm test
node node_modules/typescript/bin/tsc --noEmit
```

В тестах используются отдельные временные базы и тестовые настройки. Проверяются авторизация, источник запроса, валидация, повторная отправка, конкурентное редактирование, история, сохранность после перезапуска и отчёты. Тест интеграции занимает порт 34219; он должен быть свободен.

## Устройство

- `app/workspace.tsx`, `app/globals.css` — интерфейс React.
- `app/model.ts` — модель, валидация и форматирование.
- `standalone/server.mjs` — HTTP-сервер, вход и SQLite для собственного сервера.
- `standalone/main.tsx`, `vite.standalone.config.ts` — сборка интерфейса для Node-варианта.
- `db/schema.ts`, `drizzle/` — описание таблиц и версионируемые миграции.
- `automation/` — отдельная программа отчётов и примеры.
- `deploy/` — systemd, Nginx и шаблон настроек.
- `scripts/backup.mjs` — согласованная резервная копия SQLite.
- `docs/PORTFOLIO.md` — бизнес-контекст, ограничения и сценарий показа.

Дополнительно сохранён вариант для приватного хостинга Sites: Vinext/Cloudflare Worker, D1 и авторизация платформы. Для него используются `app/page.tsx`, `app/api/tickets/route.ts`, `worker/`, `vite.config.ts` и команда `npm run build`. Файл `.openai/hosting.json` с идентификаторами хостинга Sites не публикуется. SQLite собственного сервера и D1 — разные базы; данные между ними автоматически не синхронизируются.

## Ограничения первой версии

Ввод заявок выполняет сотрудник после входа. Публичной формы клиента, ролей, файлов, платежей, уведомлений, удаления и архивирования пока нет. История содержит время и перечень изменённых полей без старых значений. Стоимость не равна выручке. Отчёт отражает текущие статусы заявок выбранной даты создания. Даты считаются по Москве.

В этой версии все записи загружаются целиком: проект подходит для демонстрации и небольшого учебного набора; большие объёмы потребуют пагинации и проверки нагрузки. До работы с реальными данными нужны согласование требований, настройка резервных копий и приёмка владельцем процесса.
